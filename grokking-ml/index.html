The big idea

Every model is a rule you could have guessed yourself

Serrano's claim is that machine learning isn't hard. You need some arithmetic, a visual imagination and curiosity. Most books show either a sea of formulas or a sea of code. He compares that to studying music only as scores and scales. There's a melody underneath, and the book tries to let you hear it.

Humans decide in two ways: by reasoning, or by drawing on experience. Machine learning is the second way, done by a computer. The computer's experience is data. Artificial intelligence is any task where a computer makes decisions. Machine learning is the part where it decides from data. Deep learning is the part of that which uses neural networks. In his transport analogy, AI is vehicles, ML is cars and deep learning is Ferraris.

Every model in the book is built the same way. You start with a simple guess, measure how wrong it is with an error function, and nudge it a little to make it less wrong. Then you repeat. Lines that move toward points, trees that ask one more question, networks that adjust their weights: all of them follow this loop.

How people (and machines) decide from experience
1

Remember. Look at past situations that were similar. For the computer, that's the dataset.

2

Formulate. Build a general rule (a model) that fits those situations.

3

Predict. Use the rule on something new.

The running example: Bob's emails

Six of Bob's last ten emails were spam, so model 1 says that a new email is 60% likely to be spam. Then you notice weekday emails are work and weekend ones are chain letters, so model 2 says weekend means spam. That rule makes you miss his weekend birthday invitation. Model 3 uses size instead: anything 10 KB or larger is spam. Combine features with weights ("day number plus size, 12 or more is spam") and you've built a classifier by hand. The computer simply tries many more rules, much faster.

Part 1 · Chapters 1–4

Foundations

What learning from data means, which kinds of problems exist, the first real algorithm (a line fitted to points), and the trap every model can fall into: memorising instead of learning.

01What is ML?

Common sense, except done by a computer

You don't need heavy math or code. You need to spot patterns, then let a computer test far more rules than you could.

  • A program is a list of instructions a person writes. Some tasks, like recognising an apple in a photo, are too hard to spell out. People learn "apple" by seeing many apples and hearing the word. Machine learning does the same thing: show many labelled examples until the pattern clicks.
  • A model is the rule used to make predictions. An algorithm is the procedure that builds the model. The two are easy to mix up, but the book keeps them apart.
  • A feature is any property of the data the model can use, such as day of the week, size or the count of a word. Picking and combining features is half the job.
  • The best rule isn't the one that fits the old data best. It's the one that generalises best to new data. This idea comes back in every chapter.
  • Formulas get the same treatment. Whenever Serrano sees a sum sign or a conditional probability, he pictures a small concrete example first, and he teaches it that way.
02Types of ML

Labels, no labels, or rewards

Whether your data comes with the answer attached decides which family of methods you use.

  • Labelled data has a column you want to predict, like the price or "spam or not". Unlabelled data has only features.
  • Supervised learning splits again. Regression predicts a number (house prices, stock prices, minutes watched). Classification predicts a category (spam/ham, dog/cat, sick/healthy).
  • Unsupervised learning simplifies data without losing much information. Clustering groups similar rows, for example in market segmentation. Dimensionality reduction merges related features, such as collapsing size, rooms and bathrooms into one "size" feature. Matrix factorisation shrinks rows and columns at once. Generative models make new data that looks like the training data.
  • Reinforcement learning has no dataset. An agent moves through an environment and collects rewards and penalties. In the book's grid world, a robot learns to reach the treasure, avoid the dragon and go around the mountain.
  • The rest of the book covers supervised learning only, because it's the natural place to start and the most widely used.

Three families of machine learning

SupervisedLearn from examples with the answer attached, then predict the answer for new rows.regression · classification
UnsupervisedNo answers. Find structure, such as groups or fewer and simpler features.clustering · dimensionality reduction · generation
ReinforcementNo data, only an environment. Act, collect rewards, and learn which moves pay off.games · robots · self-driving

Unsupervised methods are often a first step before supervised learning, for example to clean up or compress the features.

03Linear regression

Draw a line as close to the points as you can

Think of a road through a town where everyone wants to live near the road. Start anywhere, then nudge the road toward one house at a time.

  • Houses with 1, 2, 3, 5, 6 and 7 rooms cost $150, $200, $250, $350, $400 and $450. You'd guess $300 for the four-room house without thinking, and in doing so you just did linear regression: price = 100 + 50 × rooms. The 50 is the weight of the feature (price per room) and the 100 is the bias (base price). On a plot these are the slope and the y-intercept.
  • With more features nothing new happens: each feature gets its own weight, and you add them up plus the bias. With two features the line becomes a plane, and with more it becomes a hyperplane.
  • To fit the line, start with random weights, pick a random point and move the line slightly toward it. The square trick handles every case at once. Add η × (price − prediction) to the bias and η × rooms × (price − prediction) to the slope. The small number η is the learning rate. Each pass over the data is an epoch. With η = 0.01 and 10,000 epochs, the line is already good after about 50.
  • To measure a line, use an error function: the absolute error (sum of the vertical distances) or the square error (sum of their squares). In practice people use the means (MAE, MSE) or RMSE, which is back in the label's units.
  • Gradient descent is how you lower any error. You're on top of "Mount Errorest" in thick fog, so you take the step that goes down the most, then repeat. The square trick is gradient descent on the square error.
  • For curved data, use polynomial regression. Add columns for x², x³ and so on, then run the same linear algorithm. The degree is a hyperparameter, a setting you choose before training. Weights and biases are parameters, which the model learns.

The fit and its error

The red segments are the errors. The absolute error adds up their lengths and the square error adds up their squares. Training moves the line to make that total small.

One step of the square trick

A point above the line raises the line, and a point below lowers it. Points far to the right tilt it more, because their gap is multiplied by the number of rooms. The learning rate η keeps every step small.

The real-world run

On 6,207 houses from Hyderabad, India, with 39 features each, Turi Create trains a linear regression model in one line of code. The RMSE is around 3,000,000 rupees. That sounds large, but much of it comes from outliers. A model that uses only floor area gives a single line whose slope is the price per unit of area.

04Under- & overfitting

Don't bring a fly swatter to Godzilla, or a bazooka to a fly

Simple models underfit and complex models overfit. Data the model hasn't seen tells you which one you have.

  • Underfitting is like not studying enough for an exam. Overfitting is like memorising the textbook word for word and then failing the questions that are phrased differently.
  • On data shaped like a downward parabola, a line (degree 1) underfits, a parabola (degree 2) fits well, and a degree-10 polynomial passes through every point with wild swings. That last one has zero training error, so the training error alone would pick the wrong model.
  • Keep a testing set aside. High training and high testing error means underfitting. Low training but high testing error means overfitting. Low on both means a good model.
  • The golden rule: "Thou shalt never use your testing data for training." Choosing the degree by looking at test error already breaks it. The fix is a third validation set for decisions, with the test set used once at the very end. Common splits are 60/20/20 or 80/10/10.
  • Regularisation fights overfitting without trying many models. It adds a complexity penalty to the error. The L1 norm (sum of absolute weights) gives lasso regression and pushes many weights to exactly zero, which suits data with many features. The L2 norm (sum of squares) gives ridge regression and makes all weights small without zeroing them. The parameter λ sets how much complexity counts.

Three models on the same data, and the graph that picks between them

Training error always falls as the model gets more complex. Validation error falls, bottoms out and rises again. Pick the bottom, or a slightly simpler model whose error is nearly as low. The book's example lands on degree 4. The curves here are illustrative.

The roofer analogy for regularisation

Roofer 1 · bandage1,001

Leaks 1,000 mL, costs $1. Cheap but useless: underfits.

Roofer 2 · shingles101

Judged by leaks alone, roofer 3 wins. Add leaks (the error) to price (the complexity) and roofer 2 wins. Regularised error works the same way: error + λ × complexity.

Classifiers

The answer is now a category, not a number. A line splits the points, a sigmoid turns the split into probabilities, a confusion matrix shows which mistakes the model makes, and Bayes' theorem gives a model built from counting.

05The perceptron

Use a line to split the points

Give every word a happiness score, add them up, and say "happy" if the total is at least zero.

  • On an alien planet, the language has two words, aack and beep. Happy aliens say aack more often and sad ones say beep more often. The first classifier gives aack a score of +1 and beep a score of −1, then checks the sign of the total. On a plot with aack counts across and beep counts up, that rule is the line aack = beep.
  • A perceptron is a weight per feature plus a bias. It computes a score and passes it through the step function, which outputs 1 if the score is zero or more and 0 otherwise. In two dimensions the boundary is a line, and in more dimensions it is a hyperplane.
  • The bias is the alien's mood when it says nothing. A friend who stays completely silent is probably upset, so the empty sentence gets a negative bias. Long reviews tend to be angry ones, so they lean negative too.
  • Counting mistakes is a poor error function, because it's flat and gradient descent can't move on a flat surface. The perceptron error is zero for points classified correctly and |score| for misclassified ones, so a point far on the wrong side costs more.
  • The perceptron trick mirrors the square trick. Pick a random point. If it's on the correct side, leave the line alone. If not, add η × (label − prediction) × feature to each weight, and the same without the feature to the bias. The line moves toward the point. Repeat for many epochs.
  • It works for spam filters, recommendations ("will this user watch this?"), medical yes/no questions and simple images such as MNIST digits. It doesn't work for anything that can't be split by a straight line.

One step of the perceptron trick

The dashed line puts a happy point in the sad zone. The trick shifts and rotates the line a small step toward that point until it lands on the right side. Points that are already correct don't move the line at all.

06Logistic classifiers

From a hard yes/no to a probability

Swap the step function for a sigmoid and the perceptron stops saying "100% happy" and starts saying "73% happy".

  • A logistic classifier (a continuous perceptron) computes the same score, then squashes it with the sigmoid into a number between 0 and 1. A score of 0 gives 0.5, large positive scores approach 1 and large negative ones approach 0. Points far from the line get confident predictions, and points near it get uncertain ones.
  • The error is the log loss. For each point, take the probability the model gave to the correct label and compute −ln of it. Confident correct answers cost almost nothing, and confident wrong ones cost a lot. Multiplying probabilities would give tiny numbers. Logarithms turn the product into a sum. The log loss is closely related to cross-entropy.
  • The logistic trick improves on the perceptron trick. Every point moves the line: misclassified points pull it closer, and correctly classified ones push it a little further away. Updates are η × (label − prediction) × feature, the same shape as before.
  • On IMDB movie reviews, Turi Create learns a weight per word. Wonderful gets a positive weight, horrible a negative one, and the close to zero. The bias comes out positive, so an empty review reads as positive. Unhappy viewers tend to write more.
  • For more than two classes, train one classifier per class (dog, cat, bird) and combine their scores with the softmax function, which turns them into probabilities that add up to 1.

Step versus sigmoid

The sigmoid is smooth, so gradient descent can follow its slope. The step function is flat almost everywhere, which gives the algorithm nothing to follow. Its output can also be read as a probability.

07Measuring classifiers

Accuracy and its friends

A model that tells everyone "you're healthy" can be 99% accurate and still useless. You have to ask which mistakes it makes.

  • In a dataset of 1,000 patients, 10 are sick. A model that says "healthy" for everyone is right 990 times. That's 99% accuracy, and every sick patient is sent home.
  • There are two kinds of error. A false positive is a healthy patient flagged as sick, or a real email sent to spam. A false negative is a sick patient sent home, or spam that lands in the inbox. Which one is worse depends on the problem. For medical diagnosis it's the false negative. For a spam filter that deletes mail automatically it's the false positive.
  • Recall asks how many of the real positives you found, which matters for disease. Precision asks how many of your positive calls were right, which matters for spam. The F1-score is their harmonic mean and stays close to the smaller of the two. Fβ leans toward recall when β is above 1 and toward precision when it's below 1.
  • Doctors use sensitivity (the same as recall) and specificity (the share of real negatives correctly cleared). Raising the threshold of a probabilistic model trades sensitivity for specificity.
  • The ROC curve plots sensitivity against 1 − specificity for every threshold. The area under it (AUC) scores the model as a whole: 1 is perfect, 0.5 is a coin flip. You then pick the threshold whose trade-off fits the problem.

08Naive Bayes

Using probability to its maximum

Start with a rough guess (the prior), let evidence sharpen it (the posterior), and treat each piece of evidence as if it were independent.

  • Your friend tests positive for a rare disease. The test is right 99% of the time. The chance he's actually sick is under 1%, because the disease affects only 1 in 10,000 people. False alarms from the healthy majority far outnumber the true cases.
  • That's Bayes' theorem. The prior is what you know before the evidence (1 in 10,000). The event is the positive test. The posterior is the updated probability (about 0.98%).
  • Spam works the same way. If 20 of 100 emails are spam, the prior is 20%. Among the emails containing lottery, 15 are spam and 5 are ham, so the posterior for those emails is 75%.
  • With many words, the joint counts run out quickly, since few emails contain both lottery and sale. Naive Bayes assumes the words are independent given the class and multiplies their probabilities. That assumption is wrong in reality but works surprisingly well, which is where the "naive" comes from.
  • Coded from scratch on a real email dataset, the model is just a dictionary of how often each word appears in spam and in ham. Lottery shows up in 9 spam emails and 1 ham email. Sale is close to neutral, with 39 spam and 42 ham. Counts start at 1, so no word ever gets a probability of exactly zero.

For data that a single straight line can't split: ask a series of questions, stack perceptrons into layers, lift the data into more dimensions, or let many weak models vote. Then a full project on real, messy data.

09Decision trees

Split the data by asking questions

Choose the question that best separates the labels, then ask the next question inside each branch. That's the whole algorithm.

  • An app store has six users and three apps: Atom Count, Beehive Finder and Check Mate Mate. Splitting by platform gets 4 of 6 right. Splitting by age (under 20 or not) gets 5 of 6 right, because every teenager downloaded Atom Count. So age goes at the root. Inside the adult branch, platform then separates the other two apps.
  • "Best question" can be measured three ways. Accuracy is the simplest. Gini impurity is the chance that two random picks from a set have different labels: 0 for a pure set, approaching 1 for a very mixed one. Entropy is 0 for a pure set and 1 for a 50/50 split. The drop in entropy after a split is the information gain.
  • Numeric features become yes/no questions through thresholds ("age ≥ 20?"). Try every cut between neighbouring values and keep the best. Categorical features with several values get one-hot style questions.
  • Stop when a node is pure, when the depth limit is reached or when a node is too small. Without limits, a tree will memorise the data. Depth and minimum samples per leaf are the hyperparameters that prevent overfitting.
  • Geometrically, each question is a vertical or horizontal cut, so a tree divides the plane into rectangles. A regression tree uses mean squared error to choose splits and predicts the average in each leaf, which draws a staircase of flat steps.
  • In the student-admissions example with Scikit-Learn, an unrestricted tree scores 100% on the training set. That isn't a success, it's a sign of massive overfitting. Setting max_depth and min_samples_leaf produces a smaller tree with a calmer boundary.

The app-recommendation tree

Age first, because it separates better (5 of 6 against 4 of 6). Then platform within the adults. Boxes are questions and ovals are decisions.

What a tree's boundary looks like

Every question is a cut parallel to an axis. More depth means more rectangles, and with enough depth there's one rectangle per point.

10Neural networks

Perceptrons, stacked in layers

If one line can't split the data, use two lines and a third perceptron that combines them.

  • On a new planet, happy aliens sit in a region that no single line can isolate. Two lines can do it. Serrano reads them as career happiness and family happiness: an alien is happy only when both are satisfied. That AND is itself a perceptron, whose inputs are the outputs of the first two.
  • This is a neural network. It has an input layer (the features), one or more hidden layers (simple classifiers) and an output layer. Each node computes weights × inputs + bias and applies an activation function. Without that non-linearity, the stack would collapse back into a single line.
  • Training is gradient descent on the log loss again. Backpropagation computes how much each weight contributed to the error, working backwards from the output. One way to picture it: classifiers that help get a bit more say, and those that hurt get a bit less.
  • There are some pitfalls. The sigmoid is flat at both ends, so many stacked layers produce vanishing gradients. ReLU (zero for negative inputs, the identity otherwise) mostly fixes that, and tanh helps a little. Networks overfit easily, which L1/L2 regularisation and dropout counter. Dropout switches off random neurons each epoch, like training your weaker arm by tying the strong one behind your back.
  • In Keras, a circular dataset of 110 points is classified with two hidden layers of 128 and 64 ReLU nodes and a softmax output. On MNIST, a network reaches about 94% test accuracy. One miss is a sloppy 3 that looks like an 8.
  • Other architectures handle other data: convolutional networks for images, recurrent networks for sequences such as text, and GANs for generating realistic new data.

The alien-happiness network

Each blue node is a perceptron that draws one line. The red node fires only when both of them say yes, so the network's boundary is two lines meeting at a corner. Add more nodes and layers and the boundary can take almost any shape.

11SVMs & kernels

Find boundaries with style

Of all the lines that split the data, choose the one with the most room on each side. If none splits it, add dimensions until one does.

  • Many lines can classify a dataset perfectly. The best one is the line that stays far from every point, because a small wiggle won't make it misclassify anything. A support vector machine draws two parallel lines and pushes them as far apart as it can while still classifying correctly. The final boundary is the line midway between them.
  • Its error function has two parts. The classification error is the perceptron error of each of the two lines. The distance error is large when the lines are close (it's the L2 regularisation term from chapter 4 again). Lines 0.4 apart score an error of 25. Lines 0.04 apart score 2,500.
  • The C parameter sets the balance. A large C cares mostly about classifying every point, while a small C prefers a wide margin and tolerates a few mistakes.
  • The kernel method handles data that no line can split by adding clever columns. For points inside versus outside a circle, add x₁² + x₂², which lifts every point onto a bowl. A flat plane then separates them, and that plane looks like a circle from above. For XOR-like data, the product x₁x₂ does the job. That's the polynomial kernel.
  • The RBF kernel places a mountain on every point of one class and a valley on every point of the other, then cuts the landscape at a fixed height. The parameter gamma sets the width of each bump. A small gamma gives smooth, wide boundaries, and a large gamma gives tight islands that overfit.

The widest street

Only the closest points (the support vectors) decide where the street goes. A large C narrows it to avoid any mistake, and a small C widens it.

The kernel trick, in one dimension

That's the whole idea of a kernel: add a feature that lifts the data into a space where a straight boundary works. Projected back down, that boundary is a curve.

12Ensemble learning

With a little help from our friends

Many weak learners, each a little better than chance, can be combined into one strong learner that overfits less than any single big model.

  • You have a 100-question true/false exam and five friends to help. Technique 1: each friend answers a random set of questions and you take the majority answer. Technique 2: the first friend answers only what they're surest of, the next friend takes the rest, and so on. The first technique is bagging. The second is boosting.
  • Random forests (bagging) train small decision trees on random samples of rows drawn with replacement, then let them vote. A single deep tree on the spam data overfits with jagged boxes. A forest of depth-1 trees gives a smoother boundary and treats a couple of odd points as outliers.
  • AdaBoost gives every point a weight of 1 and fits a stump. It then enlarges the misclassified points so that, in total, they balance the correct ones, and fits the next stump on the reweighted data. Each learner's vote is weighted by the log-odds of its accuracy, ln(accuracy / (1 − accuracy)). A learner at 50% gets zero say, and one that's reliably wrong gets a negative vote.
  • Gradient boosting starts by predicting the average, then fits each new tree to the residuals, the part the earlier trees still got wrong. A learning rate shrinks each tree's contribution, so the model approaches the answer in small steps.
  • XGBoost builds the residual trees with a similarity score (the square of the sum of residuals divided by their count, with λ added to the denominator for regularisation). It splits where the gain in similarity is largest and prunes splits whose gain is below a threshold. Variants of it win most data competitions. A blend of many learners also won the $1 million Netflix Prize.

Bagging versus boosting

Bagging trains independent learners on random samples and averages away their noise. Boosting trains each learner to fix what the previous ones got wrong, and better learners get bigger votes.

13In practice

From messy data to the best model

Most of the real work happens before training: cleaning, encoding and choosing features. Then you compare models fairly and tune the winner.

  • The dataset is the Titanic's 891 passengers with 12 columns, labelled survived or not. Serrano notes that a 1912 dataset carries the social biases of its time.
  • Missing values. Cabin is missing 687 of 891 values, so drop the column. Age is missing 177, so fill those with the median. Embarked is missing only 2, so put those in their own class, U for "unknown".
  • Feature engineering. Models only read numbers. One-hot encode categories (sex, port) instead of numbering them, which would invent an order. Passenger class gets one-hot encoded too, because second class had the lowest survival rate, so the classes don't line up in order. Bin ages into buckets. Drop features that are useless or redundant, such as name, ticket and ID.
  • Split 60/20/20 into training, validation and test sets. Train seven models with default settings and compare them on the validation set by accuracy and F1.
  • Grid search tries every combination of hyperparameters (the SVM's C and gamma, five values each, means 25 models) and keeps the best on validation. It lifts the SVM from 0.68 to about 0.73 accuracy. K-fold cross-validation rotates which slice of the data is used for validation, so all of it gets used for both training and checking.

The pattern under every chapter

The melody behind the math

Look back over the book and one tune keeps repeating. A model is a way of scoring an example. An error function says how wrong the scores are. Training is a long series of small steps that lower the error: gradient descent, or a trick that amounts to it.

Linear regression moves a line toward a house. The perceptron pulls a line over a misclassified alien. Logistic regression also pushes correct points a little further away. A network sends blame backwards through its layers. A boosted tree fits whatever error is left. The pictures change but the procedure stays the same.

The second tune is about humility. A model that fits its training data perfectly has proven nothing. Validation data, the model complexity graph and regularisation all exist because the real goal is to do well on data the model hasn't seen yet.

Before training

  • Plot the data first. The plot often shows which model family fits.
  • Decide whether this is regression or classification, and which error is worse: a false positive or a false negative.
  • Drop columns that are mostly empty. Fill the rest with the median or an "unknown" class.
  • One-hot encode categories, bin awkward numbers, and remove useless features.
  • Split into training, validation and test sets (60/20/20 or 80/10/10) and lock the test set away.

While training

  • Start with a simple baseline, such as logistic regression or a shallow tree.
  • Choose hyperparameters on the validation set only, never the test set.
  • Draw the model complexity graph. When the validation error turns upward, stop.
  • Prefer regularisation (L1, L2, dropout, depth limits) to bigger models.
  • Use grid search for the knobs and k-fold cross-validation when data is scarce.

Judging a model

  • Don't trust accuracy on imbalanced data. Check what an "always the majority class" model would score.
  • Read the confusion matrix and see where the mistakes land.
  • Use recall when misses are costly (disease) and precision when false alarms are costly (spam).
  • Report F1, or Fβ when one side matters more.
  • Use the ROC curve and AUC to compare models, then pick the threshold the problem needs.
  • Touch the test set once. If the model fails there, start over.
